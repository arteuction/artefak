# Artefak Digital Library — Feature Register

> Този документ е официалният каталог на функциите за **Artefak дигиталната библиотека** —
> самостоятелна платформа, отделна от phygital ArteUction auction модула.
> Всяка функция е класифицирана като **MVP**, **M2** или **Rejected**.
>
> Референция: анализ на CodeCanyon stock скрипт (Laravel 9, без Stripe SDK, без покупки).
> Кодът на скрипта **не се пренася директно** — ползва се единствено като функционален
> каталог и UX референция (виж [Защо не copy-paste](#защо-не-copy-paste)).

### Rejected — Не се имплементира

| Функция | Причина |
|---------|---------|
| Password-protected книги (plaintext) | Паролата в stock скрипта е plain text. При нашия access control модел (purchase / role) допълнителна парола е излишна и рискова. |
| Директен файл download без access check | Stock скриптът не проверява дали файлът принадлежи на книгата. Нашият download е само чрез signed URL с access middleware. |
| Stock Stripe таб от скрипта | Закоментиран, без SDK, без таблици. Не се използва нищо от него. |
| PDF/EPUB маршрути без purchase check | Съществуват в скрипта. Ние ги заменяме изцяло. |
| External URL fetch без SSRF guard | `file_get_contents($external_url)` → SSRF. Отхвърлено. |
| `GET /books/{id}/delete` | Мутиращ GET. Заменяме с `DELETE`. |
| `dev-master` зависимости | Не се внасят в production `composer.json`. |
| `.env` с реални ключове в ZIP | Никога в git. CI ползва `.env.example`. |

## Финансов модел

> **Решението за revenue split на книгите е продуктово и трябва да се вземе отделно
> от ArteUction.**

Двата кандидата:

| Модел | Автор | Фонд | Операции | Приложимост |
|-------|-------|------|----------|-------------|
| **90 / 10** | 90 % | — | 10 % | Чисто marketplace без благотворителна цел |
| **45 / 45 / 10** | 45 % | 45 % | 10 % | ArteUction модел — висок социален компонент |
| **Хибриден** | 70–80 % | 10–20 % | 10 % | Баланс — по-атрактивен за автори |

**Правило:** split профилът се замразява при момента на продажбата. Промяна в
платформения модел не засяга минали транзакции.

Решението определя структурата на `settlement_profiles` за библиотеката и трябва да
бъде взето преди имплементация на финансовия слой (MVP точки 24–27).

## Защо не copy-paste

Кодът на CodeCanyon скрипта се ползва само като UX и функционален каталог.
Директен пренос е неподходящ поради:

| Проблем | Риск |
|---------|------|
| Laravel 9 + `dev-master` зависимости | Несъвместимост и непредвидими updates |
| Plaintext book passwords | Директна уязвимост |
| Download без ownership check | Всеки може да изтегли чуждо платено съдържание |
| PDF/EPUB routes без purchase gate | Bypass на access control |
| External URL fetch (`file_get_contents`) | SSRF |
| `GET` за изтриване | CSRF, accidental delete от crawlers |
| Липса на тестове (само примерни) | Нулево покритие |
| `.env` в ZIP | Credential leak ако се commit-не |
